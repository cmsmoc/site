🏛️ 1. Introdução e Contexto Institucional

O Conselho Municipal de Saúde de Montes Claros (CMSMOC) é o órgão colegiado deliberativo superior do Sistema Único de Saúde (SUS) no município. O plenário é composto paritariamente por 64 conselheiros (32 titulares e 32 suplentes) organizados em 4 segmentos representativos:

Segmento Proporção Titulares Suplentes Total de Cadeiras
Usuários do SUS 50% 16 16 32 conselheiros
Trabalhadores da Saúde 25% 08 08 16 conselheiros
Prestadores de Serviços 12,5% 04 04 08 conselheiros
Gestão / Governo Municipal 12,5% 04 04 08 conselheiros
🎯 Objetivo da Solução Integrada
Prover uma plataforma sem atrito, rápida e resiliente que permita ao Secretário Executivo gerenciar quórum de abertura (1/3) e deliberação (50% + 1), controlar presenças em tempo real (presenciais ou via Google Meet), atualizar o portal público sem necessidade de edição de código e gerar comunicação visual institucional com agilidade e padronização.

🌐 2. Topologia do Sistema e Fluxo de Dados

A arquitetura do sistema adota o paradigma JAMstack Híbrido acoplado ao Google Workspace. Essa abordagem elimina a necessidade de servidores dedicados de backend (como Node.js ou PHP mantidos 24/7), garantindo alta disponibilidade com custo zero de infraestrutura e resposta imediata aos cidadãos e conselheiros.

⚡ 3. O Módulo de Presença (Google Apps Script)

Hospedado no diretório Docs/Reunioes/Modulo_PRESENCA, este módulo é o centro de controle da Secretaria Executiva dentro da planilha oficial.

3.1. `Código.js`: Funções-Chave e Engenharia

A. Sincronização Dinâmica com a Aba de Conselheiros

Antes desta atualização, a interface Assistente.html dependia exclusivamente de um array fixo codificado no HTML. Agora, o sistema adota uma abordagem resiliente em duas camadas: 

function obterConselheirosAba() {
  try {
    const ss = SpreadsheetApp.getActiveSpreadsheet();
    const aba = ss.getSheetByName("CONSELHEIROS");
    if (!aba) return null;

    const dados = aba.getDataRange().getValues();
    if (dados.length <= 1) return null;

    const cabecalho = dados[0].map(c => String(c).trim().toUpperCase());
    const idxId = cabecalho.indexOf("ID");
    const idxSeg = cabecalho.indexOf("SEGMENTO");
    const idxCad = cabecalho.indexOf("CADEIRA");
    const idxEnt = cabecalho.indexOf("ENTIDADE");
    const idxNome = cabecalho.indexOf("NOME DO CONSELHEIRO");

    const lista = [];
    for (let i = 1; i < dados.length; i++) {
      const r = dados[i];
      if (!r[idxNome] || String(r[idxNome]).trim() === "") continue;
      lista.push({
        id: idxId !== -1 ? r[idxId] : i,
        segmento: idxSeg !== -1 ? r[idxSeg] : "Geral",
        cadeira: idxCad !== -1 ? r[idxCad] : "Titular",
        entidade: idxEnt !== -1 ? r[idxEnt] : "",
        nome: String(r[idxNome]).trim()
      });
    }
    return lista;
  } catch (err) {
    return null;
  }
}
💡 Vantagem Técnica da Solução
A indexação dinâmica pelos nomes das colunas (indexOf) garante que, mesmo se o operador da planilha inserir novas colunas ou mudar a ordem física das células, o script continuará lendo corretamente os dados de cada conselheiro.

B. Padronização e Limpeza da Aba ADMIN

A função padronizarAbaAdmin() organiza a aba em blocos estruturados e rotulados com ==. Durante a exportação para o GitHub, o algoritmo descarta deliberadamente os cabeçalhos de seção: 

// Filtra linhas organizacionais para não sujar o JSON público

3.2. `Assistente.html`: Interface do Secretário

A interface de controle de frequência durante a reunião exibe em destaque o status da conexão da fonte de dados:

  • 🟢 Fonte: Aba CONSELHEIROS (Tempo Real) — Indica que os dados vieram da planilha.
  • 🟠 Fonte: Fallback CSV — Indica que a chamada falhou e o sistema usou com sucesso a base de contingência de 64 membros de PRESENÇA - CONSELHEIROS.csv.

💻 4. O Portal Web e a Integração Front-end

No diretório site/, as páginas públicas consomem o arquivo data/dados_reuniao.json de forma transparente e performática.

4.1. Pop-up Dinâmico na Página Inicial (`index.html`)

O script carregarDestaquesEPopup() busca as configurações mais recentes. Se a chave POPUP_ATIVO estiver configurada como "NÃO", o modal é desativado na hora, impedindo pop-ups indesejados fora de períodos de reunião.

4.2. Carrossel de Destaques no Topo (`#cms-destaques-topo`)

Injetado logo após a tag </header>, o carrossel exibe comunicados com estilo visual baseado nos tokens do CMS:

  • Navegação Híbrida: Compatível com toque (swipe) em celulares e botões direcionais (◀ ▶) em desktops.
  • Auto-Ocultação Inteligente: Caso não haja cards com destino "topo" ou a flag DESTAQUES_TOPO_ATIVO seja "NÃO", o container permanece em display: none;, sem ocupar espaço visual na tela.

🎨 5. CMS Cards Studio (`card-editor.html`)

Adaptado a partir dos modelos originais, o CMS Cards Studio foi concebido para resolver o gargalo de tempo na produção de materiais gráficos para redes sociais e para o site.

⚡ Prioridade: Agilidade com Qualidade Máxima
O operador não precisa criar um design do zero. O Cards Studio carrega 10 modelos pré-prontos com paleta institucional, tipografia equilibrada e pesos calibrados. Basta selecionar o modelo desejado, alterar os textos e exportar.

Recursos Principais do Studio:

  1. Renderização em Alta Resolução (Retina 2x): O Canvas interno renderiza as imagens com o dobro dos pixels reais da tela, garantindo que o arquivo final exportado não apresente borrões ou pixelização.
  2. Exportação Multiformato:
    • PNG: Para preservar transparências e máxima fidelidade gráfica.
    • JPEG Comprimido: Ideal para carregamento imediato em redes sociais (WhatsApp, Instagram, etc.).
  3. Minibiblioteca Local: Permite salvar rascunhos e modelos diretamente no localStorage do navegador, sem risco de perda ao fechar a janela.
  4. Controle de Destino: Checkboxes integrados para escolher onde o card será utilizado: no carrossel de destaques do topo, no pop-up do index ou na tela de presença.

🧪 6. Sandbox Administrativo (`admin-sandbox.html`)

O Sandbox Executivo é um ambiente 100% isolado, projetado especificamente para o Secretário Executivo testar fluxos completos sem tocar em nenhum registro real.

🔒 Garantia de Isolamento de Dados
O Sandbox opera estritamente na memória volátil do navegador. Nenhuma chamada de rede grava dados na planilha e nenhum commit é disparado para o GitHub.

Capacidades de Teste do Sandbox:

  • Simulação de Quórum em Massa: Botões para preencher instantaneamente 1/3 do colegiado (22 presentes), maioria deliberativa (33 presentes) ou totalidade (64 presentes).
  • Alternância de Modos: Permite testar a transição entre o Modo 1 (chamada aberta) e o Modo 2 (encerramento e liberação de declarações).
  • Simulador de Declarações de Participação: No Modo 2, o secretário clica em qualquer conselheiro presente e visualiza a declaração individual idêntica à que será impressa ou baixada pelo conselheiro.
  • Prévia ao Vivo do Pop-up da Index: Permite testar se o texto da pauta coube confortavelmente no layout antes de autorizar a publicação no portal oficial.

📋 7. Procedimentos Operacionais (Passo a Passo)

Roteiro prático para o operador da Secretaria Executiva durante o ciclo completo de uma reunião plenária:

Etapa 1: Convocação (2 a 3 dias antes)

  1. Abra a planilha oficial e acesse o menu ⚙️ CMS Presença > 🎛️ Painel de Controle.
  2. Na aba Parâmetros, atualize o número da reunião, data, horário e pauta.
  3. Na aba Pop-up do Site, clique em ⚡ Copiar Dados da Reunião Atual, revise o texto e garanta que o toggle Ativar Pop-up esteja ligado.
  4. Clique no botão 🚀 Salvar & Sincronizar com GitHub. O portal público receberá os novos dados em segundos.
  5. (Opcional) Abra o CMS Cards Studio, gere o card da convocação e exporte o JPEG para compartilhamento no grupo de WhatsApp dos conselheiros.

Etapa 2: Abertura da Sessão (Dia da Reunião)

  1. Abra o Assistente de Frequência no menu da planilha.
  2. Verifique se o indicador superior exibe 🟢 Fonte: Aba CONSELHEIROS.
  3. À medida que a lista for sendo chamada ou os conselheiros entrarem na sala do Google Meet, marque os registros de presença ou ausência.
  4. Acompanhe o painel de quórum deliberativo para informar à Mesa Diretora quando houver quórum qualificado (33 votos).

Etapa 3: Encerramento da Sessão (Pós-Reunião)

  1. Acesse novamente o Painel de Controle.
  2. Altere o Modo de Operação para 2 - Encerrada (Download de Declarações).
  3. Na aba do Pop-up, mude o toggle para Desativar Pop-up.
  4. Clique em 🚀 Salvar & Sincronizar com GitHub. O site fechará o credenciamento e liberará o download das declarações para os conselheiros presentes.

⚠️ 9. Observações e Recomendações Técnicas

  1. Uso de Aspas na Planilha: Ao preencher pautas com citações, utilize aspas simples ('texto') ou aspas tipográficas (“texto”) para evitar conflitos na serialização JSON.
  2. Validade do Token GitHub: Monitore a data de expiração do GH_TOKEN cadastrado na aba ADMIN para que a sincronização não falhe silenciosamente.
  3. Cache de Navegadores: O sistema aplica automaticamente ?t=timestamp em todas as requisições AJAX do portal, prevenindo que usuários móveis visualizem informações defasadas.

🚀 10. Sugestões para Próximos Aperfeiçoamentos

Para a continuidade da modernização dos sistemas da Secretaria Executiva, propõem-se as seguintes melhorias para o ciclo futuro:

  1. Assinatura Digital com QR Code / Hash SHA-256: Implementação de um identificador criptográfico único em cada Declaração de Participação emitida, com leitor de validação no portal do CMS para facilitar a verificação pelos setores de Recursos Humanos dos órgãos empregadores.
  2. Disparo Automático de Convocações via WhatsApp API: Integração da função de sincronização com a API de mensagens, enviando a pauta e o link do Meet diretamente para os celulares cadastrados dos 64 conselheiros.
  3. Automação de Cabeçalho da Ata: Gerador automático que preenche o preâmbulo da Ata oficial do plenário com a relação nominal de todos os titulares e suplentes que registraram frequência na sessão.
  4. Upload Direto de Atestados de Ausência: Campo de formulário em reuniao.html permitindo o envio de PDF ou foto de atestados médicos ou ofícios de justificativa diretamente para uma pasta do Google Drive da secretaria.
